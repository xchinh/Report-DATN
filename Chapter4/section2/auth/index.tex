\subsection{Phân hệ Xác thực và Quản lý Phiên (Auth Module)}
\label{subsec:module_auth}

\subsubsection{Mô tả Nghiệp vụ và Yêu cầu Chức năng}
Phân hệ Xác thực và Quản lý Phiên đóng vai trò là cửa ngõ an ninh cho toàn bộ ứng dụng di động MyHCMUT, chịu trách nhiệm xác thực danh tính người dùng qua máy chủ xác thực tập trung của Nhà trường (HCMUT CAS SSO) hoặc tài khoản nội bộ, quản lý phiên làm việc đa miền qua cơ chế Dual-Token, tự động làm mới phiên ngầm (Silent Refresh) và cung cấp giải pháp One-Time Ticket SSO cho phép người dùng mở các phân hệ Web chuyên sâu mà không cần đăng nhập lại:

\begin{itemize}
    \item \textbf{Đăng nhập tập trung CAS SSO / Nội bộ:} Hỗ trợ đăng nhập thông qua giao thức CAS SSO của Trường ĐHBK hoặc nhập tên đăng nhập và mật khẩu nội bộ.
    \item \textbf{Lưu trữ an toàn Token:} Lưu trữ mã hóa chuỗi Access Token và Refresh Token trong SharedPreferences/Secure Storage, tích hợp bộ đệm In-Memory truy xuất tức thì $O(1)$.
    \item \textbf{Làm mới phiên làm việc ngầm (Silent Refresh):} Tự động bắt lỗi HTTP 401 Unauthorized tại \texttt{MultiDomainAuthInterceptor} để kích hoạt luồng làm mới token ngầm mà không làm gián đoạn trải nghiệm người dùng.
    \item \textbf{Cơ chế One-Time Ticket SSO cho Web App:} Cung cấp cơ chế cấp vé dùng một lần (TTL 60s, Single-use trên Redis) cho phép ứng dụng di động mở các phân hệ Web mở rộng qua WebView/InAppBrowser an toàn, không truyền JWT trực tiếp trên URL.
\end{itemize}

\hline
\textbf{Tác nhân} & Cán bộ, giảng viên có nhu cầu mở phân hệ Web phụ trợ từ Mobile \\
\hline
\textbf{Tiền điều kiện} & Cán bộ đã đăng nhập hợp lệ trên ứng dụng di động MyHCMUT. \\
\hline
\textbf{Hậu điều kiện} & Ứng dụng Web mở ra trên WebView với phiên làm việc đã được xác thực tự động (không cần đăng nhập lại). \\
\hline
\textbf{Luồng sự kiện chính} & 
1. Cán bộ nhấn chọn một tính năng chuyên sâu cần mở giao diện Web trên ứng dụng Mobile. \newline
2. Ứng dụng Mobile gọi API \texttt{POST /api/auth/sso/generate-ticket} gửi kèm thông tin định danh và đích đến (\texttt{targetApp: 'hrm-fe'}). \newline
3. Backend sinh vé ngẫu nhiên UUID 32 ký tự, lưu vào Redis với TTL 60 giây và trả về cho Mobile. \newline
4. Mobile mở In-App WebView tải URL đích đính kèm vé: \texttt{https://domain/feature?ticket=xyz}. \newline
5. Web Frontend phát hiện tham số \texttt{ticket}, gọi \texttt{POST /api/auth/sso/consume-ticket} để đổi lấy phiên làm việc. \newline
6. Backend kiểm tra và xóa vé trên Redis (Single-use), cấp Session Cookie (\texttt{connect.sid}) cho Web Frontend. \newline
7. Web Frontend làm sạch thanh URL qua \texttt{window.history.replaceState} và hiển thị trực tiếp màn hình chức năng. \\
\hline
\textbf{Luồng ngoại lệ} & Nếu vé quá hạn 60 giây hoặc đã bị tiêu thụ trước đó $\rightarrow$ Backend trả về HTTP 401 $\rightarrow$ Web App chuyển hướng sang màn hình đăng nhập chuẩn. \\
\hline
